# Attorney extraction accuracy update

## Evidence and scope

The user supplied a run export containing 51 records, 59 successfully read pages,
one oversized-page failure, and 257 queued URLs left after the configured budget.
29 of the exported record names/URLs match non-person page patterns (services,
locations, notices, articles, request forms). This is a diagnostic count, not a
precision estimate. The remaining 22 records have not all been manually verified.

## Changes

- Reject non-person page headings as profiles using page purpose, rather than
  capitalization alone. Continue extracting supported person cards on those pages.
- Require profile evidence for headings and card targets; unknown capitalized
  headings alone no longer establish a person.
- Prioritize people directories and profile URLs over services, legal notices and
  articles. Apply the same ranking to sitemap links. Crawl budgets remain intact.
- Avoid classifying a person's profile header as an organization-wide header.
- Recognize phone ownership in bounded, named contact controls and profile contact
  blocks. Retain office/support/fax protections and conservative ownership when
  evidence is ambiguous.
- Preserve explicit international phone prefixes instead of losing those contacts
  or interpreting a substring as a US phone. No country is guessed for local numbers.
- Parse mailto recipients without harvesting CC/BCC/body email addresses.
- An incidental unassigned contact on another record no longer demotes its explicit
  individual owner to an organization contact. Conflicting individual assignments
  remain conservative.

The preceding UI changes remove classification labels and use neutral Completed
labels while retaining page failure details. They do not establish data accuracy.

## Validation

153 automated tests passed, including non-person headings, real card extraction on
service pages, profile-header contacts, international contact controls, support
contact isolation, ownership aggregation and a three-page-budget crawl that reaches
an attorney profile before an unrelated privacy page. Lint and JavaScript syntax
checks passed. Browser acceptance covers upload, run controls, directory, exports,
races, responsive layout and inert rendering of HTML.

Fresh HTML was retrieved using the environment's standard HTTP route from:

- https://www.littler.com/people/nicola-james
- https://www.littler.com/people/stephan-c-swinkels
- https://www.littler.com/people/kate-mrkonich-wilson
- https://www.littler.com/people

The extractor produced exactly one named record on each profile, with its published
email. Nicola's two international phones and Stephan's international phone were
retained as individual contacts; Kathryn's US phone remained unassigned because
its surrounding contact controls did not establish ownership unambiguously.
The directory produced no false person record, but its initial HTML did not expose
its JavaScript-loaded directory results. This is a remaining discovery limitation.

These were real HTML extraction checks, not successful end-to-end production crawls.
The production secure Fetcher still encountered DNS resolution failure in this
runtime. BakerLaw and Fisher Phillips direct HTML requests returned HTTP 403.
No access restrictions were bypassed or production transport protections weakened.

## Remaining limits

- No broad site-level precision/recall percentage has been established.
- JavaScript-only directory pagination needs a separate supported discovery path.
- Office vs personal contact ownership remains conservative when source context is
  ambiguous; mailbox delivery is not tested.
- Existing stored observations are not retroactively rewritten. Start a fresh run
  to obtain results from the improved extractor.
- Push and native Windows validation remain pending.
